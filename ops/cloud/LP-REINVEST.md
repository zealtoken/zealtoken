# zZEC LP fee reinvestment

Policy: collect fees from the wallet-owned zZEC/ETH position #1909208, allocate 100% of each token to reinvestment for owner 0x1C083F2f85aCadae452C7512C45cD7c8a3ddbF03. This does not change the pool's 0.3% LP fee or the immutable hook's 0.7% output charge. The hook continues funding the Furnace. No reserve funds, keeper trading inventory, or LP principal are allocated to this strategy. Keeper pays execution gas.

`ZealLpReinvest.sol` is a non-upgradeable helper approved for this specific NFT only. The NFT remains in the owner's wallet. The helper can only collect zero-liquidity decreases and increase that same position. It cannot transfer NFTs, decrease principal, call arbitrary targets, or pull tokens from the owner. The constructor validates owner, pool and tokens. After every collection/increase it verifies the position's liquidity. Approval can be revoked directly on PositionManager. This is newly written code, tested against a fork of the deployed contracts; it has not received an independent security audit.

All collected fees in each token remains available in the helper. Compounding uses matching amounts only; unmatched funds wait there and remain withdrawable by the owner. There are no balancing swaps. These funds are still at smart-contract risk. `withdrawFees()` sends uninvested funds to the immutable owner. `setPaused(true)` disables collection/reinvestment but leaves this withdrawal available. Fully withdrawing the original LP prevents further compounding. LP withdrawals remain owner-controlled through PositionManager regardless of helper approval.

AWS checks hourly, requiring at least $5 of actual matched liquidity and a conservative transaction-cost bound at most 2% of that value. It only adds when the pool is within 1% of the Coinbase/Kraken reference. Transactions include pool/reference price bounds, a minimum added-liquidity amount, and a short on-chain deadline. Owner credentials stay on the Mac; the existing keeper credential calls the helper on AWS, using the existing wallet lock and persistent pending-transaction reconciliation.

Deployment configuration and code hash: `cloud/lp-reinvest.json`. Runtime checks the code hash, immutable settings, NFT ownership and per-position approval. `zeal-lp-reinvest.timer` runs every hour after completion. `/etc/zeal/LP_REINVEST_ACTIVE` is required in addition to ACTIVE. `cloud/health.py` monitors failed or stale runs and uses the existing Gmail alerts. Normal below-threshold waits are successful runs, not errors. Transaction receipts/events are recorded in `launchd/lp-reinvest-<tx>.json`; on-chain FeesSplit/Reinvested events remain authoritative if a process crashes after confirmation.

Recovery: stop/disable the timer, let an active service finish, then remove LP_REINVEST_ACTIVE. Inspect any pending keeper transaction and on-chain events before retrying. To stop at contract level, the owner can pause the helper or revoke its NFT approval. To recover everything, withdraw uninvested helper fees and remove the NFT's liquidity through PositionManager. Never send the NFT to the Furnace or to the helper. Never upload the owner key to AWS.

One-time setup uses `src/lp-reinvest-setup.ts` on the Mac, with the Mac runtime OPS_STATE_DIR to coordinate owner signing. It checks compiled versus deployed runtime code, verifies immutable values, grants only the specific NFT approval and simulates collection before cloud activation. The setup script is not included in the cloud release. Install `cloud/install-lp-reinvest.py`, verify configuration and read-only simulation, then activate and verify the first service run.
